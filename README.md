# TSW - Fabric mod (Minecraft 1.21.11)

نظام اختيار شخصيات (3 خانات) لكل لاعب، كل خانة تحمل حفظ (Save) مستقل تمامًا
(إنفنتري، موقع، صحة، جوع، XP، البعد/الدايمنشن)، بسكن مخصص يُدخل كرابط URL،
مع شاشة اختيار سينمائية تفتح تلقائيًا أول ما يدخل اللاعب السيرفر ومعاينة
3D متحركة (دوران) للشخصية بالسكن المختار.

## كيف تبنيه (Build)

هذا المشروع مصدر كامل جاهز، لكن بناءه إلى ملف `.jar` يحتاج إنترنت (لتحميل
mappings ومكتبات ماين كرافت عبر Fabric Loom) وجهاز عليه:

- Java 21 (JDK)
- إنترنت شغال (أول بناء فقط، يحمّل ويكاش المكتبات)

الخطوات:

```bash
cd tsw-mod
./gradlew build
```

(على ويندوز استخدم `gradlew.bat build` - إذا ملف الـ wrapper `gradlew`/`gradlew.bat`
مو موجود، شغّل `gradle wrapper` مرة عشان يتولّد، أو افتح المشروع في IntelliJ
IDEA مع Minecraft Development plugin وخله يتولى التنزيل تلقائيًا).

ناتج البناء يطلع في: `build/libs/tsw-1.0.0.jar` — هذا هو ملف المود، ضعه في
مجلد `mods` بسيرفرك (Fabric Loader + Fabric API لازم يكونوا مثبتين على
السيرفر، ونفس نسخة المود على كلاينت كل لاعب).

## تحقّق قبل البناء

في `gradle.properties`، أرقام نسخ `yarn_mappings` و `fabric_version` قد
تتغيّر بشكل متكرر. افتح https://fabricmc.net/develop/ قبل البناء وتأكد إنها
مطابقة لآخر إصدار متوافق مع 1.21.11، وحدّثها إذا احتاجت.

## الملفات المهمة

| الملف | المسؤولية |
|---|---|
| `TSWMod.java` | نقطة الدخول العامة: تسجيل الشبكة، فتح شاشة الاختيار عند الدخول، استقبال اختيار/إنشاء الشخصية |
| `character/CharacterProfile.java` | بيانات خانة واحدة (سكن + NBT كامل للاعب) |
| `character/CharacterManager.java` | حفظ/تحميل/تبديل الخانات على القرص (`world/tsw/playerdata/<uuid>/slotN.dat`) |
| `network/TSWNetworking.java` | كل الباكتات بين الكلاينت والسيرفر |
| `TSWClient.java` | نقطة دخول الكلاينت: يفتح الشاشة، يستقبل بث السكن |
| `client/gui/CharacterSelectScreen.java` | الشاشة نفسها: 3 خانات + معاينة 3D دوّارة + حقل رابط السكن |
| `client/skin/SkinCache.java` | تحميل صورة السكن من الرابط وتحويلها لتكستشر داخل ماين كرافت |
| `mixin/client/AbstractClientPlayerEntityMixin.java` | يبدّل السكن المعروض فعليًا للاعب بالتكستشر المخصص |

## قرارات تصميم مهمة

- **الباند حسابي تلقائيًا بدون أي كود إضافي**: نظام الباند في ماين كرافت
  (`banned-players.json`) مربوط بـ UUID الحساب الحقيقي، وكل الخانات الثلاث
  تستخدم نفس UUID (نفس الحساب) - فباند الإدارة يطبّق على اللاعب بغض النظر
  عن أي خانة كان فيها.
- **كل خانة = حفظ مستقل بالكامل**: عند التبديل، يتم أخذ NBT الكامل للاعب
  الحالي (إنفنتري/موقع/صحة/XP...) وحفظه في ملف الخانة القديمة، ثم تحميل
  وتطبيق NBT الخانة الجديدة. أول دخول لخانة فاضية = شخصية جديدة بحالة
  افتراضية (سبون العالم، إنفنتري فاضي).
- **الشاشة تفتح دائمًا عند الدخول** (لا تُغلق بـ Escape) — يعني كل جولة
  اتصال باللاعب لازم يختار/يأكد خانة قبل ما يواصل اللعب، حسب طلبك.
- **السكن**: اللاعب يكتب رابط PNG مباشر (256×64 أو 64×64) في حقل الشاشة،
  يضغط "حفظ السكن" لتثبيته على الخانة، والمود يحمّله ويعرضه فعليًا على
  جسم اللاعب (لنفسه وللاعبين الآخرين عبر بث تلقائي).

## نقاط تحتاج انتباه بعد البناء (لأني ما قدرت أبني/أختبر المشروع فعليًا هنا)

بيئة التنفيذ عندي بلا إنترنت، فما قدرت أشغّل `gradle build` ولا أتحقق من
توافق كل اسم دالة (mapping) مع 1.21.11 بالضبط. الأماكن الأكثر عرضة لحاجتها
تعديل بسيط (سطر أو اسم دالة فقط، المنطق ثابت):

1. `AbstractClientPlayerEntityMixin` — اسم الدالة `getSkinTextures` قد
   يختلف بنسخة يارن مختلفة.
2. `CharacterSelectScreen.renderRotatingPreview` — استدعاء
   `InventoryScreen.drawEntity(...)` قد يحتاج تعديل عدد/ترتيب البارامترات
   حسب نسخة يارن بالضبط.
3. `gradle.properties` — أرقام `yarn_mappings` / `fabric_version` (راجع
   الفقرة أعلاه).

باقي الكود (الشبكة، حفظ/تبديل الخانات، تحميل السكن) لا يعتمد على أي API
متغيّر بسرعة، ومفروض يبني كما هو.
